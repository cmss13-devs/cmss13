/datum/mapgrid

Organizes 2D space in-game for fast searching and ranging queries

Vars

bounds_xX boundaries of the map cells mapgrid x coordinate -> game x coordinate example: 1 => 40, 2 => 80, 3 => 110, 4 => world.maxx+1
bounds_yY boundaries of the map cells
cellsx -> y -> /datum/mapcell
dimDimensions of the map grid: 4 -> 4x4 -> 16 cells Cannot be changed after instantiation
tracked_atomsList of the contained atoms and their respective mapcell - maps /atom/movable -> /datum/mapcell

Procs

check_atom_locWhere the update part of the magic happens - when mapcoords propagates updates, we need to ensure that the atom is positioned correctly within the mapgrid This is going to get called a lot of times, so ensure it stays simple
forgetRemoves a movable from the mapgrid
handle_expansionUpdates the mapgrid when world is expanded Again this does not rebalance right away, this can be done later by SS
init_partitionPartitions the mapgrid, for now to be used only at init, it does not preserve state
insertInserts an atom with a MapCoords component into the mapgrid
query_rangeWhere most of the magic happens - scans a range over several mapcells in the mapgrid to perform a ranging query. Watch out, for compatibility reasons with external code, the range is inclusive both directions here. If provided, z_list allows to filters results by exact zlevel, for multiz use. This is provided for convenience, I encourage you to take all the results and handle them appropriately in your code instead.
scan_new_boundsScans new boundaries to use when we'll rebalance the grid later new_bounds_x and new_bounds_y are output not input, they should be a list of length [dim]
