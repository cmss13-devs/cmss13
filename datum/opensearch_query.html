/datum/opensearch_query

Models a single instance of an OpenSearch query to be used The query can be changed over time, and this datum also serves as the handler of the tgui associated with viewing the search

Vars

error_textLast error message if applicable
idNumerical ID used to reference the search internally and in links
log_typesFilter for the type of logs to view. If empty, show everything.
nameUser given name to the query
query_resultsRaw results of the last query, as stringified JSON, to be passed to TGUI for parsing clientside
query_statusCurrent status of the query
range_queryRanging part of the filter, allowing an user to set to only display events near a position
ranking_modeIf true, we sort by query score instead of by time
roundidRound ID to look at
time_agoHow long ago to stop search, this lets us look further back in time unbothered or do simple pagination If this is 3600 for example, we'll search from forever ago to 1 hour ago. The beginning range is configured separately in config entries.
user_queryThe actual Lucene query text that the user is requesting. It'll be mashed with everything else.

Procs

NewCreate a query with bootstrap query text
bootstrap_lucene_dslCreates the base DSL for executing a Lucene based search
build_dslBuilds the query DSL based on the query builder parameters This returns either null on success or an error message
create_dashboards_linkCreates the Link to Dashboards for our query
create_dashboards_lucene_queryCreates an expanded Lucene query with additional filters that are normally injected into the DSL This is because passing filters and such in a Dashboards URL is very unwieldy. So instead, we just do best-effort by shoving equivalent filters into the Lucene query. Note that this doesn't include the time filter, which we can set easily in URL.
create_lucene_queryCreates the full Lucene query for use by us All the extras handled here could be injected into the DSL instead, but this requires more intricate handling of internal state and UI work.
executeLaunches the query, returning an error text if something went wrong
inject_parameters_in_dslAdds additional query builder parameters into the DSL
on_errorCallback for an errored HTTP request (probably at network level)
on_successCallback for a successful request
render_time_paramGets the correct time string for a given time
